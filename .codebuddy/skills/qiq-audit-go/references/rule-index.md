- 保留原文第 18 行的内部使用限制；不访问内部链接、不公开分发。
- 用本索引选择原文段落并跟踪覆盖，不用索引代替原文。行号范围指随附原文，不是被审代码。
- ID 按章节与主题稳定命名，`GO-章节-主题`；同一 ID 内各子条件均应审核。一个主题包含不同等级时分成不同 ID。

## 分级原则

1. 优先使用条款自身的显式 `【必须】` / `【推荐】` / `【可选】`；没有显式标记时继承最近的有等级标题。
2. 章节概述和工具附录没有等级，不擅自列为必须或推荐违规。可将信息作为证据或待确认项。
3. 保留例外和条件，不把自然语言“建议”“尽量”“一般”变成无例外绝对规则。若明确规则与上下文冲突，列待确认，不自行改变原规范。
4. §2.5.1 的错误构造建议、§6.3 的接收器命名建议按推荐；§6.3 禁用 `me/this/self`、§6.4 文件长度按必须。
5. §2.4 的第三方别名修正、匿名 import 分组/注释为可选，不进入两个违规列表；`embed` 的匿名引用无需注释。
6. §2.6 的测试函数长度 160 行和测试文件 1600 行继承该节必须标题；§6.4 的普通函数 80 行按显式推荐标记处理，分别跟踪，不因阈值倍数关系降级单测规则。
7. §7.2 的 `go.sum` 提交要求继承推荐标题，虽然句中有“必须提交”，未带独立 `【必须】` 标记，不升级为门禁错误；报告注明依据 §7.2。
8. 原文提到圈复杂度与普通代码保持一致，但未给阈值，不新增 10、15 等门禁条件。不新增测试覆盖率比例，也不要求测试全部使用唯一命名形式。

## 误报防护与证据要求

- 对 import 真正包名、error 类型、内置调用/被遮蔽名字、结构体字面量、别名和接口方法集优先查 LSP/类型信息，缺依赖时降级而不假定。
- 对错误明确 `_` 忽略、`defer Close`、panic 合法情形、recover 类型筛选、循环立即调用闭包、生成代码豁免及非导出接收器注释逐项复核。
- 对文件名问题定位 `<file>` 与实际第一行；文件超限定位首次超限行并给总数；包注释缺失定位现存 package 声明；测试缺失定位被测导出函数/服务入口，而非杜撰测试文件行号。
- 对 module/README/go.sum 等缺失文件写 `—（文件缺失）`，给现存辅助锚点；对未跟踪/忽略问题给 Git 证据。
- 对超过阈值报告实测值、阈值、计数口径；阈值相等不违规。
- 对变更审核核对新旧行号和影响，不混入无关历史问题。对增删导致包级/项目级问题按现存位置锚定。

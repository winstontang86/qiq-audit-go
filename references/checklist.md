# 检查项 Checklist（机读 + 人工 review 双轨）

> 规则全文见 `full-spec.md`（`GO-*` 编号的唯一来源，表内行号范围均指该文件）：863 行，SHA-256 `b115f9addd86fc244aa6860b937342752e18f4d35939217ef7d699d33b6a3e82`。规范更新后需同步本表行号与该校验值。
>
> 本表把条目按「工具可直接判定」与「人工 / AI review」分类：
>
> - **工具**：由 `gofmt`、`goimports` 或 `scripts/go_index.go` 给出客观事实（格式差异、分组顺序、函数范围、行数、参数个数），比对阈值即可判定。
> - **人工 / AI**：工具只给定位线索，结论需结合类型信息、调用关系与业务上下文判断。
>
> `scripts/go_index.go` 仅索引与计数，**不产出违规清单**：工具区条目仍需 agent 运行工具后自行比对判定。
> 本 skill 只检查必须（MUST）与推荐（RECOMMEND）等级；可选（OPTIONAL）不检查。

## 二、人工 / AI review（manual）

| 编号 | 等级 | 类别 | 检查内容与例外 |
| --- | --- | --- | --- |
| GO-2.5.1-ERROR-HANDLE | MUST | 错误处理 | 返回的 `error` 必须处理、传播或显式 `_` 忽略；`defer xx.Close()` 可不显式处理。须由函数签名/类型确认返回值确为 `error`，显式忽略不算违规。 |
| GO-2.5.1-ERROR-TEXT | MUST | 错误处理 | 错误描述不以标点结尾。检查最终文本，而非 `%w` 前的上下文冒号；格式字符串末尾未知时不得定罪。 |
| GO-2.5.1-ERROR-FLOW | MUST | 错误处理 | 独立错误流：错误分支处理后返回/继续，正常代码不放对应的 `else`。需确认分支确实退出及初始化值的后续使用。 |
| GO-2.5.1-ERROR-COND | MUST | 错误处理 | 错误判断独立，不与其他变量条件组合。需与局部判断、错误包装核对后定位具体条件。 |
| GO-2.5.1-ERROR-NEW | RECOMMEND | 错误处理 | 不需格式化的错误用 `errors.New`（如 `fmt.Errorf("plain text")`）。注意转义 `%%`、动态内容与真实调用对象，不凭字符串正则断言。 |
| GO-2.5.1-ERROR-WRAP | RECOMMEND | 错误处理 | Go 1.13+ 包装错误建议 `fmt.Errorf("module xxx: %w", err)`。结合是否需保留错误链与业务目的，纯字符串错误不强制 `%w`。 |
| GO-2.5.2-PANIC | MUST | 错误处理 | 不用 panic 处理一般错误或用户输入；允许不变量断言、影响程序运行的 `init`/全局初始化失败。必须 panic 的导出方法用 `MustXXX` 命名并说明；不把 main 中所有 `log.Fatal` 判错（原文仅为"不建议"，结合断言用途确认）。 |
| GO-2.5.3-RECOVER | MUST | 错误处理 | 必须在 `defer` 中有效直接调用；捕获明确 panic 类型并重抛不认识的类型，不滥用捕获一切。`defer recover()`、由 deferred 函数再调普通辅助函数中的 recover 均不构成有效恢复。业务代码使用 recover 的必要性需上下文。 |
| GO-3.1-PACKAGE-DOC | MUST | 注释 | 除 main 外每包有 `// Package 包名 …` 注释，同包任一文件即可；按整个包检查，不逐文件报缺失。考虑 build tags、外部 `_test` 包与生成文件来源。 |
| GO-3.2-STRUCT-DOC | MUST | 注释 | 导出结构体/接口定义前有以名称开头的说明；导出字段中生僻或含义不明的需注释。与 GO-3.5-TYPE-DOC 重叠时合并；"生僻"先看领域上下文。 |
| GO-3.3-FUNC-DOC | MUST | 注释 | 导出函数/方法与导出接口内的方法有名称开头的说明；非导出类型接收器的方法可不注释；测试文件导出函数可不注释。原文列举的 `Write Read ServeHTTP String Unwrap Error Len Less Swap` 按对应用途豁免，不扩大到同名业务函数。原文示例 `NewtAttrModel` 名称拼写不一致，以正文名称要求为准。 |
| GO-3.4-VALUE-DOC | MUST | 注释 | 导出变量/常量有前置注释并以名称开头，`//` 后一个空格；大块声明可总说明 + 逐行末尾说明。不能凭 `GenDecl` 已有文档就认定组内每个成员都已说明。 |
| GO-3.5-TYPE-DOC | MUST | 注释 | 导出类型定义与类型别名都有前置说明并以名称开头；含非结构体类型，注意声明组内逐项文档。 |
| GO-4.1-PACKAGE-NAME | RECOMMEND | 命名 | package 与目录一致、简短有意义、小写、无下划线与混合大小写，避免与标准库冲突及 `util/common/misc/global` 泛包名。main、外部测试 `pkg_test`、版本目录等生态约定结合上下文，不机械误报；`xx/util/encryption` 允许。 |
| GO-4.2-FILE-NAME | MUST | 命名 | 有意义且简短；小写、单词用下划线分隔。保留 `_test`、平台/架构后缀等 Go 约定；无法确认语义时不硬判。 |
| GO-4.3-STRUCT-NAME | MUST | 命名 | 驼峰，首字母按可见性；名词或名词短语、不用动词，避免 `Data`/`Info` 等过宽名称。结合完整领域名判断，不按子串机械禁止 `UserInfo`。 |
| GO-4.4-INTERFACE-NAME | RECOMMEND | 命名 | 同结构体命名规则；单方法接口以 `er` 结尾，两方法综合命名，三个以上类似结构体名。考虑嵌入接口的方法集；原文未规定 3 方法的硬边界。 |
| GO-4.5-VAR-NAME | MUST | 命名 | 驼峰且首字母按访问控制；专有名词私有首词小写、其余保持原写法（`APIClient`/`repoID`/`UserID`）；私有全局与局部变量均小写开头；命名长度与使用距离匹配。生成代码可豁免；`_` 不是违规。 |
| GO-4.6-CONST-NAME | MUST | 命名 | 常量驼峰，私有首字母小写；枚举常量先定义对应类型。`HTTP`/`HTTPS` 等规范缩写允许全大写，不机械要求含小写字母。 |
| GO-4.7-FUNC-NAME | MUST | 命名 | 函数驼峰且按可见性大小写；生成工具代码可豁免（含已证实的 gotests 生成命名）；手写测试允许原文指定的下划线形式。 |
| GO-5.1-IF-INIT | RECOMMEND | 控制结构 | 适用的 `if` 局部初始化用短声明；与「返回值需在 if 之后使用」兼容，不把有后续用途的变量强塞进 if 作用域。 |
| GO-5.1-IF-COMPARE | RECOMMEND | 控制结构 | 两个值比较时变量在左、常量在右；两侧均为变量或常量时不适用。 |
| GO-5.1-IF-BOOL | RECOMMEND | 控制结构 | bool 直接判断真假，不与 `true`/`false` 比较；先确认类型，`*bool`、接口等不机械改写。 |
| GO-5.2-FOR | RECOMMEND | 控制结构 | 用短声明建立循环局部变量；需在循环外保留或复用变量时不机械建议改作用域。 |
| GO-5.3-RANGE | MUST | 控制结构 | 只需 key 时省略第二项；只需 value 时第一项置 `_`。字符串/整数 range 等语义不同的循环不强改双值；已使用的变量不要求额外丢弃。 |

| GO-5.5-EARLY-RETURN | RECOMMEND | 控制结构 | 错误尽早 return 以降嵌套；与 GO-2.5.1-ERROR-FLOW 重叠时归入必须项并附本 ID，不双计数。 |
| GO-5.6-GOTO | MUST | 控制结构 | 业务代码禁止 goto。先判断代码归属，框架/底层源码走 GO-5.6-GOTO-LOWLEVEL。 |
| GO-5.6-GOTO-LOWLEVEL | RECOMMEND | 控制结构 | 框架或底层源码尽量不用 goto；不是业务代码的绝对禁令，特殊需要先查证。 |
| GO-6.1-RESULT-NAME | RECOMMEND | 函数 | 返回两三个相同类型结果、或从上下文看不清含义时用命名返回，其他情况不建议；按展开的返回参数与语义核验。 |
| GO-6.1-PARAM-NAME | RECOMMEND | 函数 | 输入参数与命名返回变量以小写字母开头；忽略未命名参数与 `_`。 |
| GO-6.1-PARAM-VALUE | RECOMMEND | 函数 | 尽量值传递；`map`/`slice`/`chan`/`interface` 不传指针。考虑修改调用者变量、可空语义、锁与大对象等实际需要及类型别名，不无脑禁用所有指针。 |
| GO-6.2-DEFER-RESOURCE | MUST | 函数 | 资源申请成功、错误判断之后紧跟 `defer` 释放；需确认资源所有权、是否转移给调用方、生命周期与实际释放 API，不需释放的对象不要求 defer。 |

## 三、分级原则

1. 优先使用条款自身的显式 `【必须】` / `【推荐】` / `【可选】`；无显式标记时继承最近的有等级标题。
2. 章节概述与工具附录无等级，不擅自列为必须或推荐违规，可作证据或待确认项。
3. 保留例外与条件，不把"建议""尽量""一般"变成无例外绝对规则；明确规则与上下文冲突时列待确认，不自行改写规范。
4. §2.5.1 的错误构造建议、§6.3 的接收器命名建议按推荐；§6.3 禁用 `me`/`this`/`self`、§6.4 文件长度按必须。
5. §2.4 的第三方别名修正、匿名 import 分组与注释为可选，不进入两个违规列表；`embed` 匿名引用无需注释。
6. §2.6 的测试函数 160 行、测试文件 1600 行继承该节必须标题；§6.4 的普通函数 80 行按显式推荐标记处理，二者分别跟踪，不因阈值倍数关系降级单测规则。
7. §7.2 的 `go.sum` 提交要求保留等级歧义（见上表说明），确认前不得据此单独给出"必须规则通过"以外的更强结论。
8. 原文提到圈复杂度与普通代码保持一致但未给阈值，不新增 10/15 等门禁条件；不新增覆盖率比例，也不要求测试全部使用唯一命名形式。

## 四、违规级别说明

- **MUST（必须）**：不允许存在，发现即阻断合流；结论为"未通过"。
- **RECOMMEND（推荐）**：原则上应遵守，特殊情况可放行但需说明；不改变必须规则通过结论，但计入改进数量。
- **OPTIONAL（可选）**：本 skill 不检查。

## 五、误报防护与证据要求

- import 真实包名、error 类型、builtin 与被遮蔽名称、结构体字面量、接口方法集：优先查 LSP/类型信息，缺依赖时降级而不假定。
- 逐项复核：`_` 显式忽略、`defer Close()`、panic 合法情形、recover 类型筛选、循环内立即调用闭包、生成代码豁免、非导出接收器无需注释。
- 定位要求：文件名问题定位 `<file>` 与实际首行；文件超限定位首次超限行并给总数；包注释缺失定位现存 `package` 声明；测试缺失定位被测导出函数或服务入口，不得杜撰测试文件行号。
- 缺失文件（`go.mod`/`go.sum`/README）写 `—（文件缺失）` 并给现存辅助锚点；未跟踪/被忽略问题须给 Git 证据。
- 超阈值项报告实测值、阈值与计数口径；恰好等于阈值不算违规。
- 变更审核核对新旧行号与影响，历史问题单列；增删导致的包级/项目级问题按现存位置锚定。
- 覆盖状态与违规数量是两套统计：同一问题跨规则合并后，相关 rule_id 仍标记"存在违规"。

## 六、不进入违规列表的项目

- §2.4 的两个【可选】建议与 `embed` 例外。
- §3 章节概述（同步写注释、所有导出名字文档、清理注释掉的代码）：未独立标等级，不擅自新增必须 ID；其中可明确检查的部分用 §3.1–3.5 条目覆盖，其余作为待确认项，允许提示但不得静默跳过。
- 工具附录（`gofmt`/`goimports`/`go vet`/`golint` 说明）：不要求安装已过时的 Gometalinter/golint，也不要求执行被审项目代码。
